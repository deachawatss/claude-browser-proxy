## Honest Feedback

**Friction 1: Misread the user's intent.** The user showed a Gemini page screenshot and said "show quick link to canvas mode." I built it in the side panel instead of the page itself. The screenshot WAS the context — they were looking at the Gemini page and wanted the button THERE. I should have noticed the existing injected buttons (⚡💭🧠🔬) in the input area and realized that's where it belonged.

**Friction 2: Over-investigated the MQTT routing.** When the user said "still nothing" I went deep into tracing the MQTT publish-subscribe loop, checking if commands round-trip correctly through the broker, examining timestamp filtering. None of that was relevant — the user just wanted an injected DOM button on the page. I spent several turns investigating plumbing when the answer was a simple DOM addition.

**Friction 3: Didn't explain the content script reload requirement clearly enough.** After the first "still nothing" screenshot, the buttons weren't showing because content scripts need a page refresh after extension reload. I should have led with that immediately instead of investigating code paths.

## Lessons Learned

- When a user shows a screenshot, the screenshot IS the specification. Build the feature where they're pointing.
- Content scripts in Chrome extensions require a page refresh after extension reload — always remind users of this.
- The `.includes()` string matching pattern for menu items is fragile — exact first-line matching prevents cross-contamination between items with descriptions.
